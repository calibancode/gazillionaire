# Code map

Raw application source: `$GAZ_DATA_DIR/src/decompiled/scripts/`.
`GAZ_DATA_DIR` defaults to `.local-data/`; `tools/export_all.sh` creates the
extraction. Raw source is local and ignored by Git. `app/src/` is generated by
`tools/prepare_build.py`; make reconstruction changes in the preparation tools.

The [game reference](GAME_MECHANICS.md) indexes the system descriptions.
Source references use function names and raw extraction line numbers.

| Class | Purpose |
|---|---|
| `Gazillionaire` | UI and game logic |
| `GameStrings` | English strings, names and event text |
| `GameType` | Session state and serialization |
| `PlayerType`, `OpponentType` | Human and AI state |
| `CustomPreloader`, `LoadScreen` | Startup UI |
| `Gazillionaire_*Class`, `*_dataClass` | Embedded assets |

`frm_<Screen>_<action>` methods implement screen behavior. `__frm_*` methods
and hash-prefixed fields are generated Flex bindings. Bundled `mx.*` and
`spark.*` classes come from the SDK during reconstruction.

`g.p` contains human players, indexed from zero; `g.o` contains opponents,
indexed from one. A planet slot (0–6) is translated through `g.planetIndex`
to a planet identity (0–13). `frame_globals` is temporary screen state: its
indices change meaning between screens. For example, the market uses index
109 for its selected row, while the supply screen uses it for a UI control.
Popup callbacks such as `doAmount` dispatch on the active screen, so reading
only the screen's buy/sell methods misses part of a transaction.

## Reading the UI code

`mainCanvas.selectedChild` drives screen transitions; a screen's `show`
handler calls its load/setup routine. Popup actions dispatch on that active
screen. Stage counters in `frame_globals` resume event chains after a dialog,
so successive independent `if` blocks may deliberately advance several stages
in one call. Replacing them with `else if` changes behavior.

`doAmount` strips every non-digit from its input before conversion and caps
the result at 100 billion. Decimal separators and minus signs are removed,
not interpreted. Its screen-specific branch then checks the amount.

Names beginning `__frm_` wire mouse/keyboard/Flex events to those handlers.
The remaining generated factories, bindings and property accessors construct
the interface. They account for much of the main class's size; begin a rule
investigation with the `internal function` implementations around lines
45423–71315, then follow their callbacks and state mutations.

`GameStrings.getString` returns a diagnostic for missing keys. The released
language selector offers English only: `setLanguage` ignores its argument
and initializes the same English table. String keys help identify related
screens and event branches, but explanatory text is not proof that a charge
or protection occurs; check the adjacent state writes.
